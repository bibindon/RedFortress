## 目的

ステージクリア用ポータル（現状：単なる赤いキューブ）を、3段階の状態遷移を持つ祭壇デザインに変更する。

**状態遷移設計：**
1. **石段**（2×2m、3段ピラミッド、最上段に立つスペース）：常時表示、物理コリジョンで登れる
2. **光の円柱**（高さ20m、発光、アニメなし）：全敵撃破で出現。コード側スケール制御で伸長演出
3. **黒い旗**（ポール＋布、なびくアニメ付き）：プレイヤーが最上段に登ると出現 → クリア確定

---

## スコープの範囲

本計画は **Blenderモデリング＋.xエクスポート** に限定し、C++ゲーム側の実装（状態遷移ロジック、コリジョン登録、CSV更新）は含まない。これは別タスクで実施する。

## パート1：Blender モデリング & .x エクスポート

### 1.1 共通セットアップ（3モデル共通）
- **出力先**：`RedFortress2/MultiPassRendering/res/model/` 配下に新規ディレクトリ `portal/` を作成
- **生成スクリプト**：`tools/BuildPortalModels.py` を新規作成（`CreateGrassModel.py` の慣例パターンを踏襲）
- **Blender実行**：`C:\Program Files\Blender Foundation\Blender 5.1\blender.exe --background --python tools/BuildPortalModels.py`
- **エクスポート設定**（AGENTS.md準拠）：`axis_forward="-Z"`, `axis_up="Y"`、`global_scale=1.0`
- **エクスポート後正規化**：BOM-less UTF-8、CRLF（`CreateGrassModel.py:90-96` の `normalize_x_file` を流用）
- **座標系**：Y軸が上、1単位=1メートル

### 1.2 モデル1：石段 `stone_steps.x`（静的、コリジョン用も兼ねる）
- **形状**：3段のピラミッド状石段
  - 最下段：2.0×2.0m、高さ0.5m（Y=0.0〜0.5）
  - 中段：1.6×1.6m、高さ0.5m（Y=0.5〜1.0）
  - 最上段：1.2×1.2m、高さ0.5m（Y=1.0〜1.5）←プレイヤーが立つスペース
- **テクスチャ**：`stone_steps.png`（石の質感、Blender内 `bpy` 画像APIで生成。Pillow非依存）
- **マテリアル**：通常ディフューズ（発光なし）
- **エクスポート**：`export_armature=False`, `export_weights=False`, `export_animation=False`
- **コリジョン用**：同じ形状を `stone_steps_collision.x` としても出力（`XFileListPhysics.csv` 登録用）

### 1.3 モデル2：光の円柱 `light_pillar.x`（静的、発光）
- **形状**：円柱（半径0.4m、高さ20m）、原点を底面中心に配置（Y=0〜20）
- **テクスチャ**：`light_pillar.png`（白〜青の縦方向グラデーション、半透明）
- **発光設定**：`meshtype=Emit`、`EmitColor,200,230,255`、`EmitIntensity,0.5` を記述した `light_pillar.csv` を同梱
- **エクスポート**：静的（アニメなし）
- **演出**：出現時の伸長はC++側でスケールYを0→1にアニメーション（本タスクでは実装しない）

### 1.4 モデル3：黒い旗 `black_flag.x`（ボーンアニメ付き）
- **形状**：旗ポール（高さ2.0m、黒い金属）＋ 布メッシュ（横1.2m×縦0.8m）
- **ボーン構造**：3本のボーン（`pole`、`cloth_top`、`cloth_bottom`）を布にバインド
- **アニメーション**：`wave`（布がなびくループ、2秒周期）。`AnimTicksPerSecond=4800`（marine実績に準拠）
- **出力構成**（marineパターン準拠の分離方式）：
  - `black_flag.x`：メッシュ＋ボーン＋SkinWeights（ベース）
  - `black_flag.wave.x`：`AnimationSet "wave"` を含むアニメーション専用
  - `black_flag.csv`：`Anim, "wave", "black_flag.wave.x", loop`
- **テクスチャ**：`black_flag.png`（黒い布、ポール用金属テクスチャを含むアトラス）
- **エクスポート**：`export_armature=True`, `export_weights=True`, `export_animation=True`

### 1.5 テクスチャ生成方針（Pillow非依存）
- Python 3.13 に Pillow が無いため、Blender のバンドル Python 内で `bpy.data.images.new()` + ピクセルアクセス（`image.pixels`）で procedural に生成
- 石：グレー系ノイズテクスチャ
- 光の柱：白〜青の縦グラデーション、Alpha付き
- 旗：黒一色＋微細な布地ノイズ、ポール部分はダークグレー

### 1.6 検証
- 生成後、各 `.x` ファイルの先頭（`xof 0303txt 0032`）、`Frame Root`、`AnimationSet`（旗のみ）、`Material`、`TextureFilename` が正しく含まれるかを Read で確認
- `AnimTicksPerSecond` が 4800 であることを確認（旗）
- BOM が付いていないこと（`.x` は BOM-less）、CRLF であることを確認

## リスクと対策

| リスク | 対策 |
|---|---|
| Blender 5.1 公式 X エクスポータのアニメ出力がエンジン非互換 | marine 系と同じ `AnimTicksPerSecond=4800`/`AnimationSet`/ボーン名一致の実績パターンに厳密に従う |
| 旗のボーン/SkinWeights が正しく出力されない | エクスポート後 `.x` を grep で `SkinWeights`/`XSkinMeshHeader`/`AnimationSet` の存在を必ず確認 |
| Pillow 未インストール | Blender バンドル Python の `bpy` 画像APIでテクスチャ生成し、外部依存を排除 |
| 軸の不一致（AGENTS.md） | `axis_forward="-Z"`, `axis_up="Y"` を固定（`CreateGrassModel.py` 実績） |
| テクスチャパス解決 | `TextureFilename` はファイル名のみ（相対パス）、モデルと同ディレクトリに配置 |

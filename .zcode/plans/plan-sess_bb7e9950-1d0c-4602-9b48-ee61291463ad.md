# Spiderモデル IK削除 ＋ アニメーション再作成 計画

## 根本原因（特定済み）

`.x` に **39個のボーン**が含まれ、そのうち **10個がIK制御ボーン**（Foot ×8 + PoleTarget ×2）です。これらは `Root` の直下に置かれ、**脚チェーン（FrontLeg.L → FrontLeg2.L → FrontLeg3.L）から切り離されています**。

致命的なのは、これらIKボーンが **`SkinWeights` にも登録され、各96〜101頂点（計約800頂点）を実際に変形させている** ことです。IKボーンは位置キーだけで独立して動くため、脚チェーンの回転アニメーションから頂点が「剥がれて」単独で跳ね回り＝ゲーム上の表示崩れになります。

`source.blend` 側ではすでに IK コンストレイント自体は削除されていますが、IK制御ボーンの存在とベイク痕跡が残存しているのが現状です。

## 方針

**アプローチ：IKボーン10本を完全削除し、ウェイトを脚チェーンの先端ボーンへ移植。全アクションを FK ベイクし直してクリーンな `.x` を再エクスポート。ゲーム側 C++ は一切変更しない。**

`AGENTS.md` の「Blender公式エクスポータを使う」「loaderを書き換えない」方針に合致します。Skeleton/Golem と同じ（IKボーンの無い）健全な構造になります。

## 実装ステップ

### Step 1: 新規スクリプト `tools/RemoveSpiderIK.py` を作成

`source.blend` を開き、以下を自動実行（元ファイルは非破壊、別名保存）：

1. **IK制御ボーン10本をアーマチュアから削除**
   - 削除対象: `FrontFoot.L`, `FrontFoot2.R`, `MidFrontFoot.L`, `MidFrontFoot.R`, `BackFoot.L`, `BackFoot.R`, `MidBackFoot.L`, `MidBackFoot.R`, `PoleTarget.L`, `PoleTarget.R`
   - 対応する `*_end` Empty も親関係と一緒に削除

2. **頂点ウェイトを脚チェーン先端へ移植**（各メッシュに対し）
   - 削除するIKボーンの頂点グループのウェイトを、対応する脚先端グループへ加算:
     - `FrontFoot.L` → `FrontLeg3.L`, `FrontFoot2.R` → `FrontLeg3.R`
     - `MidFrontFoot.L/R` → `MidFrontLeg3.L/R`, `BackFoot.L/R` → `BackLeg3.L/R`, `MidBackFoot.L/R` → `MidBackLeg3.L/R`
     - `PoleTarget.L/R` は頂点0なので無視
   - 移植後、IKボーンの頂点グループを削除し、各頂点のウェイトを正規化

3. **全アクションの FK ベイク**
   - 各アクション（Idle/Walk/Jump/Attack/Death）の全フレームを走査し、`bpy.ops.nla.bake(visual_keying=True, clear_constraints=False, use_current_action=True, bake_types={"POSE"})` で **脚チェーン全ボーン（24本）＋ Body/Head/Abdomen/Thorax** のローテーションをクリーンなFKキーとして上書き
   - これでIK残滓が完全に消滅

4. **クリーンアップしたモデルを `Spider_clean.blend` として保存**

### Step 2: 再エクスポート

Step1のクリーンアップ済み `.blend` を `PrepareEnemyModels.py` の spider 設定を使って公式エクスポータで `.x` 出力：
- `enemy.x`, `enemy.default.x`, `enemy.idle.x`, `enemy.move.x`, `enemy.fast_move.x`, `enemy.attack.x`, `enemy.hit.x`, `enemy.death.x`, `enemy.csv` を生成（既存ファイルを上書き）

### Step 3: 検証

- 出力 `.x` の `SkinWeights` ボーン数が **29個**（39 − IK10）になっていることを確認
- `Frames` 数も29個（IKボーンFrameが消滅）を確認
- `validate_x_file` の既存チェックを通過することを確認
- `enemy.csv` の内容が変わらないことを確認

### Step 4: バックアップ

- 現行の `source.blend` と `.x` 群は `Spider_backup/` へコピーして保護（削除しない）
- 新しい `Spider_clean.blend` を `Spider/` に置く

## リスクと対策

- **リスク**: ウェイト移植で足先の変形が変わる可能性
- **対策**: ウェイトを「加算」ではなく脚先端グループがすでに持っている比率で統合し、正規化。検証はBlenderでのスクリーンショット確認と、ゲームでの目視で実施
- **リスク**: 他の敵モデル（Skeleton等）への影響
- **対策**: Spider専用スクリプトのみ作成。C++（CustomXLoader2）には一切触らない

# Quaternius敵モデル（蜘蛛・骸骨・キノコ・ゴーレム）の追加実装計画

## 調査の結論

**Ghost敵は既にQuaterniusモデル**（`res/model2/Ghost/source.glb`、SOURCE.md に Quaternius + poly.pizza クレジット）として取り込まれており、**Quaternius GLB → Blender → `PrepareEnemyModels.py` → `enemy.x`** のパイプラインは実証済みです。今回の4種も全く同じ手法で取り込めます。

### 入手元（2パックで4種すべて揃う、すべてCC0・`.blend`/FBX/glTF 同梱）
| 敵 | パック | モデル名 |
|---|---|---|
| 蜘蛛 | **Easy Enemy Pack** | Spider |
| 骸骨 | **Ultimate Monsters Pack** | Skeleton |
| キノコ | **Ultimate Monsters Pack** | Mushnub（基本種） |
| ゴーレム | **Ultimate Monsters Pack** | Goleling（基本種） |

## 作業の分担（重要）

このタスクは **Blender を動かす環境が必要な部分** と **C++ コードを書く部分** に分かれます。

### 🧑‍💻 ユーザーが実行する作業（私が代替不可）
1. 上記2パックをダウンロードして `.glb` を抽出
2. 各 `.glb` を所定フォルダに配置
3. Blender を起動して `PrepareEnemyModels.py` を実行（軸設定・検証はスクリプトが自動処理）

2. 4つの C++ 敵クラス作成
3. `simple-directx9.vcxproj` / `.filters` への登録
4. `EnemyManager` への登録
5. ステージCSV（`stage1/EnemyPositions.csv`）へのテスト配置

## 実装ステップ

### ステップ1：アセット フォルダ作成（ユーザー）
各敵のフォルダとソースGLBを配置：
```
res/model2/Spider/    ← source.glb, spider.png（テクスチャ）
res/model2/Skeleton/  ← source.glb, skeleton.png
res/model2/Mushroom/  ← source.glb, mushnub.png
res/model2/Golem/     ← source.glb, goleling.png
```
※テクスチャ名は各GLBを開いて確認後、ASSET_CONFIGS と一致させます。

### ステップ2：`tools/PrepareEnemyModels.py` の `ASSET_CONFIGS` 拡張（私）
Ghost の設定を参考に、4エントリを追加。Quaternius モデルは概ね以下の命名規則を持つため、これを初期値とします（実行時の検証エラーで微調整）：
```python
"spider": {
    "armature": "SpiderArmature",  # GLBを開いて確認
    "texture_filename": "spider.png",
    "actions": {
        "idle": "SpiderArmature|Idle",
        "move": "SpiderArmature|Walk",
        "fast_move": "SpiderArmature|Run",
        "attack": "SpiderArmature|Attack",
        "hit": "SpiderArmature|Hit",
        "death": "SpiderArmature|Death",
    },
},
# skeleton / mushroom / golem も同様
```
Ghost の実績から、Quaternius 系は `"<ArmatureName>|<ActionName>"` 形式のアクション名を使う傾向があります。正確なアーマチュア名・アクション名はGLBをBlenderで開いた際に確認します。

### ステップ3：Blender エクスポート実行（ユーザー）
各モデルについて：
```
blender --background --python tools/PrepareEnemyModels.py -- spider res/model2/Spider/source.glb res/model2/Spider/
```
スクリプトが `enemy.x`、`enemy.{default,idle,move,fast_move,attack,hit,death}.x`、`enemy.csv` を生成し、BOM/CRLF/SkinWeights/マテリアルを検証します。

### ステップ4：4つの C++ 敵クラス作成（私）
`EnemyCrab.cpp` / `EnemyFrog.cpp`（Ground 移動の既存パターン）をテンプレートに作成：

**`EnemySpider.h/.cpp`**（地面移動・高速）
```cpp
EnemySpider(pos, meshId, yaw)
  : EnemyBase(pos, meshId, L"spider", yaw,
              maxHp=10, moveSpeed=3.5f, viewDistance=12.0f,
              contactRadius=0.55f, height=0.4f,
              MovementMode::Ground, /*usesExtendedAnimations=*/true) {}
static float GetScale() { return ?; }  // GLB確認後決定
```
**`EnemySkeleton.h/.cpp`**（地面移動・中速・やや頑強）
**`EnemyMushroom.h/.cpp`**（地面移動・低速・高HP）
**`EnemyGolem.h/.cpp`**（地面移動・低速・超高HP・大型）

ステータス・スケール値は GLB を開いて実寸を確認してから決定します（1unit=1m、プレイヤー高さ1.7m 基準）。

### ステップ5：プロジェクトファイル登録（私）
`simple-directx9.vcxproj` と `.filters` に4クラスの `ClCompile`/`ClInclude` エントリを追加（EnemyCrab のパターンに倣う）。

### ステップ6：`EnemyManager` 登録（私）
- `EnemyManager.cpp` 先頭に `#include "EnemySpider.h"` 等4つを追加
- `RegisterEnemyTypes()` に4行追加：
```cpp
RegisterEnemyType<EnemySpider>(L"spider", L"Spider", L"enemy.x", L"enemy.csv");
RegisterEnemyType<EnemySkeleton>(L"skeleton", L"Skeleton", L"enemy.x", L"enemy.csv");
RegisterEnemyType<EnemyMushroom>(L"mushroom", L"Mushroom", L"enemy.x", L"enemy.csv");
RegisterEnemyType<EnemyGolem>(L"golem", L"Golem", L"enemy.x", L"enemy.csv");
```

### ステップ7：テスト配置（私）
`res/model/stage1/EnemyPositions.csv` に4体を追加：
```csv
Type,PosX,PosY,PosZ,RotY
...（既存）
spider,3.0,0.2,12.0,0
skeleton,-3.0,0.2,12.0,0
mushroom,6.0,0.2,-12.0,0
golem,-6.0,0.2,-12.0,0
```

### ステップ8：ビルド検証（私）
```
MSBuild.exe RedFortress2\MultiPassRendering.sln /p:Configuration=Debug /p:Platform=x64
```
コンパイルエラーがなければ完了。実行して表示確認するのはユーザー環境にて。

## AGENTS.md コンプライアンス
- ✅ 公式 Blender DirectX X exporter を使用（`PrepareEnemyModels.py` 経由）
- ✅ カスタムエクスポータ/コンバータは作らない
- ✅ `.x` は BOM-less UTF-8・CRLF（スクリプトが強制）
- ✅ `.cpp/.h` は BOM UTF-8・CRLF・PascalCase・`m_`/`k` プレフィックス
- ✅ 三項演算子不使用
- ✅ 軸設定 `axis_forward="Z"`, `axis_up="Y"` を維持
- ✅ 既存 EnemyBase サブクラス パターンに厳密に従う

## リスクと備考
- **アーマチュア名・アクション名**: Quaternius モデル固有の値は GLB を開かないと確定できません。ステップ2の値は Ghost パターンからの推測値で、実行時に検証エラーが出たら修正します。
- **テクスチャ構成**: Quaternius モデルはマルチテクスチャの場合があります。Bird の `material_textures` 辞書パターンを使う可能性があります。
- **スケール**: 各モデルの実寸確認が必要。1unit=1m 基準でプレイヤー(1.7m)と釣り合うサイズに調整します。

## 進め方
ステップ4〜7（C++ コード）は、GLB の中身が見えなくても**推定値で先行実装**できます。まずは `ASSET_CONFIGS` と4クラスを推定値で書き、ユーザーに Blender 実行してもらって検証エラーで名前を確定していく、という反復アプローチを推奨します。

私が最初に着手するのは **ステップ2（ASSET_CONFIGS 拡張）+ ステップ4〜6（C++ クラス・登録）** です。これでビルドが通る状態まで持っていき、その後ユーザーの Blender 実行結果を受けて名前・テクスチャ・スケールを確定させます。

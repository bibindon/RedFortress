# ダークソウル風ボス体力バー実装計画

## 設計の要点

プレイヤー用 `HpBar` クラスが**すでにダークソウル風**（前面バー＋遅延ダメージバーの二重アニメーション）で存在するため、これをベースにボス専用バーを作成します。最大の工夫点は**ダメージ追従の集約**で、5箇所ある被弾処理を個別に修正せず、`GameApp::DrawBossHpBar()` が毎フレーム敵リストを走査してHPを比較することで差分を検出し、バーのアニメーションを駆動します。

## 実装ステップ

### ステップ1: ボス判定の新設（`EnemyBase` + ボスクラス）

**`EnemyBase.h`** — 仮想関数を追加:
```cpp
virtual bool IsBoss() const { return false; }
virtual std::wstring GetDisplayName() const { return L""; }
```

**ボス候補クラス**（3ファイル）でオーバーライド:
- `EnemyGolem.h` → `bool IsBoss() const override { return true; }` / 名前 `L"ゴーレム"`
- `EnemyBigWolf.h` → `bool IsBoss() const override { return true; }` / 名前 `L"ウェアウルフ"`
- `EnemyGiantCrab.h` → `bool IsBoss() const override { return true; }` / 名前 `L"ジャイアントクラブ"`

> 名前は仮です。実装時にご指定いただければ調整します。

### ステップ2: `BossHpBar` クラス新設（`HpBar` をベース）

**新規ファイル**: `BossHpBar.h` / `BossHpBar.cpp`

`HpBar` との相違点:
| 項目 | HpBar（プレイヤー） | BossHpBar（ボス） |
|---|---|---|
| ターゲット | `Player*` | `EnemyBase*` |
| 位置 | 左上（`kPosY=0.05`） | **画面下部中央**（`kPosY=0.88` 相当、中央寄せ） |
| バー長 | 1000px基準 | **より長く**（例: 全幅の60%程度） |
| 名前表示 | なし | **バー上部にテキスト**（`DrawTextExCenter`） |
| アセット | `hp_*.png` を流用 | 同じ `hp_*.png` を流用（長く描画） |

遅延ダメージアニメーション ロジック（`OnDamage`/`Update`/`CalcBarWidth`）は `HpBar` からほぼそのまま流用します。

**API**:
```cpp
class BossHpBar {
public:
    void Initialize(NSRender::Render* pRender);
    void SetBoss(EnemyBase* pBoss);   // ボスを設定（null で非表示）
    void Update();                     // HP差分検出 → OnDamage 駆動
    void Draw();                       // バー＋名前描画
private:
    // HpBar と同等のアニメーション状態メンバ
    EnemyBase* m_pBoss = nullptr;
    int m_lastObservedHp = -1;         // 差分検出用
};
```

### ステップ3: ボス検索メソッド追加（`EnemyManager`）

**`EnemyManager.h/.cpp`** — 生存ボスを取得:
```cpp
EnemyBase* GetAliveBoss();       // IsBoss() && !IsDead() の最初の1体
```
`GetEnemies()` を走査するだけのシンプルなメソッド。null ならボスバー非表示。

### ステップ4: `GameApp` へ組み込み

**`GameApp.h`**:
- `#include "BossHpBar.h"`
- メンバ `BossHpBar m_bossHpBar;`

**`GameApp.cpp`** — 3箇所:

1. **初期化**（`GameApp.cpp:767` の `m_hpBar.Initialize(...)` の直後）:
   ```cpp
   m_bossHpBar.Initialize(&m_render);
   ```

2. **ステージロード時リセット**（`GameApp.cpp:2860` の `m_hpBar.Reset()` の直後）:
   ```cpp
   m_bossHpBar.SetBoss(nullptr);
   ```
   これで前ステージのボス参照をクリア。

3. **HUD描画**（5箇所の `m_hpBar.Draw()` の直後）:
   ```cpp
   m_hpBar.Draw();
   m_bossHpBar.Update();   // 生存ボスを検索 → HP差分検出 → アニメーション
   m_bossHpBar.Draw();     // ボスがいれば描画、いなければ何もしない
   ```
   対象行: `1104, 1136, 1160, 1177, 1381`

### ステップ5: `vcxproj` へのファイル登録

`BossHpBar.h` / `BossHpBar.cpp` を `simple-directx9.vcxproj`（と `.filters`）に追加しないとビルド対象になりません。既存の `HpBar.cpp` エントリを雛形に追加します。

## ダメージ追従の仕組み（工夫点）

5箇所ある被弾処理（`DamageEnemiesInAttackRange`:2811, 踏みつけ:1578/1588, 爆弾:7034, バスター:7179）を**個別に修正しません**。代わりに:

- `BossHpBar::Update()` が毎フレーム `m_pBoss->GetHp()` を読む
- 前フレームの `m_lastObservedHp` と比較し、減っていれば `OnDamage(old, new)` を呼ぶ
- これにより、**どの攻撃でダメージを受けても自動的にバーが反応**する

これにより `EnemyBase` 側に UI への依存を持たせず（関心の分離を維持）、被弾処理の修正箇所をゼロにできます。
